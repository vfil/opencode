Tool Design

How to define, register, translate, and fail a tool on every protocol. One page, printable.

The shape (provider-neutral)

type Tool = {
  name: string                              // ^[a-zA-Z0-9_-]{1,128}$
  description: string                       // 3–4+ sentences
  parameters: Record<string, unknown>       // JSON Schema, shared by both protocols
  execute: (input: unknown) => Promise<string> // validates its own input
}

const tools: Tool[] = [listFiles, readFile, editFile, writeFile, bash]

// Each protocol's definitions are derived, never written twice
const toOpenAITool = (t: Tool) => ({ type: "function", function: { name: t.name, description: t.description, parameters: t.parameters } })
const toAnthropicTool = (t: Tool) => ({ name: t.name, description: t.description, input_schema: t.parameters })

Dispatch (shared by every loop)

async function runTool(name: string, rawInput: string | unknown) {
  const tool = tools.find((t) => t.name === name)
  if (!tool) return { content: `Unknown tool: ${name}. Available: ${tools.map((t) => t.name).join(", ")}`, isError: true }
  try {
    const input = typeof rawInput === "string" ? JSON.parse(rawInput) : rawInput // OpenAI sends a JSON string
    return { content: await tool.execute(input), isError: false }
  } catch (e) {
    return { content: String(e), isError: true }
  }
}

// OpenAI protocol:    { role: "tool", tool_call_id: call.id, content: r.isError ? `Error: ${r.content}` : r.content }
// Anthropic protocol: { type: "tool_result", tool_use_id: block.id, content: r.content, is_error: r.isError }

Rules

RuleWhySource
One object per tool: name, description, schema, executor. No protocol inside. Adding a tool never touches a loop or a protocol. tool/AGENTS.md
Failures are results, never a crash. The model can recover; a crash ends the turn. Handle tool calls
Errors say what went wrong and what to try next. On the OpenAI protocol the text is the only signal. qwen3.5:9b followed "try 'src' instead" on both local providers. read.ts, shared.ts
Descriptions: what, when (and when not), each parameter, limits. "By far the most important factor in tool performance." Small models need it more. Define tools
Validate model input inside the executor, including the JSON parse. The schema guides the model; it doesn't enforce anything. Handle tool calls
Few tools; high-signal, bounded output (paginate, truncate with a notice). Definitions and results cost context every step; 32k fills fast. Writing tools for agents

Where a tool lives

Definition and dispatch are harness. Execution is sandbox, which is why permissions attach to execution, not to the registry (tool/AGENTS.md, Permissions).
