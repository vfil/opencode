Agent Architecture

The loop, the vocabulary, the wire shapes per protocol, and the three parts. One page, printable.

The loop (one turn)

  1. Send the conversation + tool definitions (name, description, JSON Schema).
  2. Model replies with text, or with tool calls (id, name, arguments).
  3. Your code runs each requested tool. The model never executes anything.
  4. Append one result per call, tied to the call's id. Go to 2.
  5. Model replies with text and no tool calls → the turn ends.

The three parts

PartIsPreventsOpenCode
Harness The loop: calls the model, routes tool calls to tools. Brittle, untestable, single-provider agents. session/runner/, packages/ai/src/llm.ts, tool.ts
Session Durable log of what happened, outside the process and the context window. Losing work on crash or restart. session/inbox.ts, session/execution.ts, session/history.ts
Sandbox Where tools touch the world, behind guardrails, without credentials. The model running anything it proposes. permission.ts, tool permission flow in tool/AGENTS.md

Rules worth memorizing

  • The model proposes; your code executes. That boundary is the only safety an agent has.
  • Same protocol, different provider: changing the base URL is enough (Ollama ↔ llama.cpp).
  • "OpenAI-compatible" is not identical: field names drift (reasoning vs reasoning_content).
  • Ollama defaults to a 4k context on small machines. Agents need 32k or more; set it explicitly.
  • Claude is the reference: if Claude succeeds where a local model fails, the model is weak; if both fail, suspect the harness.
  • Each step is one model call that continues from reloaded history. No in-memory tool loop (OpenCode).
  • This repo uses Effect v4; check the migration guide when v3 examples don't fit.
