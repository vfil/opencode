Tools as Data

Go from the three-tool array you built in Part 1 to a registry of five that both of your protocols can use, where a failing tool becomes information the model can act on instead of a crash.

First: your prediction

In Part 2 you predicted what your loop does when list_files gets a path that doesn't exist, and whether the OpenAI protocol reports failures the way Anthropic's does. Recall your answer before opening this.

What it should do, on each protocol

It should not crash, and it should not hide the failure. It should send back a normal tool result that says what went wrong. How you mark it as a failure depends on the protocol:

  • Anthropic Messages (Claude) has a flag: "is_error": true on the tool_result (Handle tool calls).
  • OpenAI Chat Completions (Ollama, llama.cpp) has no such flag. A role: "tool" message is just text, so the text is the only signal. OpenCode does the same: on this protocol an error result is simply written out as the message content (protocols/shared.ts).

This works on small local models too. In my tests, both Ollama and llama.cpp running qwen3.5:9b received "Error: directory not found: . (try listing 'src' instead)" and immediately called list_files again with "src". A clear error message is the mechanism involved, so the wording of the message matters.

A tool is one object

Agents commonly end up with the same shape. A tool is a single value holding four things: a name, a description, an input schema, and an executor (the function that does the work). Compare Thorsten Ball's Go agent with OpenCode:

Sources: How to Build an Agent; packages/core/src/tool/plugin/read.ts. OpenCode's tool/AGENTS.md makes this a rule: "Each tool carries its name, options, schemas, and executable behavior in one object."

Notice that neither object mentions a protocol. A tool is provider-neutral. Keeping it that way is what makes tools data:

  1. Each protocol's tool list is derived from the registry. One small function turns a tool into { type: "function", function: { name, description, parameters } } for OpenAI; another turns it into { name, description, input_schema } for Anthropic. Same JSON Schema, different wrapping. You never write a definition twice.
  2. Dispatch is a lookup by name. When a tool call arrives, find the tool with that name and run its executor. A tool the model asks for that you don't have isn't a crash either: Ball's agent replies "tool not found" as an error result.

Add a fifth tool and you add one object. Neither loop changes, and neither does any protocol code. This is the main result of this post.

Three rules for tools the model can use well

1. Descriptions matter most

Claude's docs call detailed descriptions "by far the most important factor in tool performance" and recommend at least 3–4 sentences: what the tool does, when to use it (and when not to), what each parameter means, and its limits. OpenCode's read description is seven sentences long, and it tells the model how to read large files ("Use offset and limit…") and when to use a different tool ("use grep to find specific content"). Anthropic's tool-design post gives a useful test: describe the tool as you would to a new hire. The advice comes from Anthropic, but it matters more for a 9B local model, which has less ability to guess what you meant.

2. Errors should say what to do next

The docs: "Instead of generic errors such as "failed", include what went wrong and what Claude should try next." Here is OpenCode doing it. When a file is missing, the read tool doesn't return "not found". It looks for similar names: 

File not found: docs/README

Did you mean one of these?
docs/README.md

Its truncation notice works the same way: [Output truncated. Continue reading with offset: 2001]. The model gets the exact next call to make. On your local providers, where there's no error flag, this text is everything.

3. Model input is untrusted

The schema tells the model what to send, but nothing forces it to comply. Claude's docs say that when input is invalid and you reply with an error result, "Claude will retry 2–3 times with corrections before apologizing to the user." Local models make this mistake more often, and the OpenAI protocol adds one more way to fail: arguments arrives as a JSON string, so JSON.parse itself can throw on a malformed reply. Treat a parse failure like any other bad input: an instructive error result, never a crash. OpenCode's registry validates model input at runtime for every tool (tool/AGENTS.md, Registration). In the Effect part, Schema will do this for you. For now, check it by hand.

Step 3: One function that never throws

runTool(name, rawArguments) is the single place where a tool call turns into a result. It takes the tool name and the arguments exactly as the model sent them (on the OpenAI protocol, a JSON string) and always returns { content, isError }. An unknown tool, invalid JSON, invalid input and an executor that throws all come back as an error result instead of ending the program. Add it below the tools array and above toOpenAITool: 

type ToolResult = { content: string; isError: boolean }

// Never throws: every failure becomes a result the model can read.
const runTool = async (name: string, rawArguments: string): Promise<ToolResult> => {
  try {
    const tool = tools.find((tool) => tool.name === name)
    if (!tool) throw new Error(`Unknown tool: ${name}. Available tools: ${tools.map((tool) => tool.name).join(", ")}`)

    let input: unknown
    try {
      input = JSON.parse(rawArguments)
    } catch {
      throw new Error(`The arguments are not valid JSON: ${rawArguments}`)
    }

    return { content: await tool.execute(input), isError: false }
  } catch (error) {
    return { content: error instanceof Error ? error.message : String(error), isError: true }
  }
}

Then replace the four lines in the loop that looked up the tool, threw for an unknown one and ran it. This is also where the Error: prefix is added, because this protocol has no error flag and the text is the only signal:

Step 4: Add write_file and bash

First the import, added at the top of the file with the others: 

import { execFile } from "node:child_process"

Then two functions, placed above the tools array:

const saveFile = async (path: string, content: string) => {
  await mkdir(dirname(path), { recursive: true })
  await writeFile(path, content)
  return `Wrote ${content.length} characters to ${path}`
}

const TIMEOUT_MS = 30_000
const MAX_OUTPUT = 10_000

const runBash = (command: string) =>
  new Promise<string>((resolve, reject) => {
    execFile("bash", ["-c", command], { timeout: TIMEOUT_MS, maxBuffer: 10_000_000 }, (error, stdout, stderr) => {
      if (error?.killed) return reject(new Error(`The command ran longer than ${TIMEOUT_MS} ms and was stopped. Try a faster command.`))
      if (error && typeof error.code !== "number") return reject(error)
      const output = `${stdout}${stderr}`
      const shown =
        output.length > MAX_OUTPUT
          ? `${output.slice(0, MAX_OUTPUT)}\n[Output truncated after ${MAX_OUTPUT} characters. Filter it with head, tail or grep.]`
          : output
      resolve(`Exit code: ${error ? error.code : 0}\n${shown}`)
    })
  })

runBash makes four decisions that determine what the model sees:

  • The result starts with Exit code: N, so cutting long output cannot hide it.
  • A non-zero exit is an ordinary result, not an error result. grep exits with 1 when nothing matches, and the model can read the code itself. OpenCode's shell tool also returns output normally and records the exit code alongside it.
  • A command that runs past 30 seconds is stopped and reported as an error result that says so. A failure to start bash is an error result too.
  • Output beyond 10,000 characters is cut, with a notice that says how to filter it.

const listFiles = async (path: string) => {
  const entries = await readdir(path, { withFileTypes: true })
  return entries.map((entry) => (entry.isDirectory() ? `${entry.name}/` : entry.name)).join("\n")

const editFile = async (path: string, oldStr: string, newStr: string) => {
  if (oldStr === newStr) throw new Error("old_str and new_str must be different")

  if (oldStr === "") {
    if (existsSync(path)) throw new Error(`${path} already exists; pass the text to replace as old_str`)
    await mkdir(dirname(path), { recursive: true })
    await writeFile(path, newStr)
    return `Created ${path}`
  }

  const content = await readFile(path, "utf8")
  const matches = content.split(oldStr).length - 1
  if (matches === 0) throw new Error(`old_str was not found in ${path}`)
  if (matches > 1) throw new Error(`old_str matches ${matches} places in ${path}; include more surrounding text`)
  await writeFile(path, content.replace(oldStr, () => newStr))
  return "OK"
}

type ToolResult = { content: string; isError: boolean }

// Never throws: every failure becomes a result the model can read.
const runTool = async (name: string, rawArguments: string): Promise<ToolResult> => {
  try {
    const tool = tools.find((tool) => tool.name === name)
    if (!tool) throw new Error(`Unknown tool: ${name}. Available tools: ${tools.map((tool) => tool.name).join(", ")}`)

    let input: unknown
    try {
      input = JSON.parse(rawArguments)
    } catch {
      throw new Error(`The arguments are not valid JSON: ${rawArguments}`)
    }

    if (tool.confirm) {
      const answer = await rl.question(`Allow: ${tool.confirm(input)}? [y/N] `)
      if (answer.trim().toLowerCase() !== "y") throw new Error("User declined this action. Ask what they would like instead.")
    }
    return { content: await tool.execute(input), isError: false }
  } catch (error) {
    return { content: error instanceof Error ? error.message : String(error), isError: true }
  }
}

  type: "function",
  function: { name: tool.name, description: tool.description, parameters: tool.parameters },
})

type ToolCall = { id: string; function: { name: string; arguments: string } }
type Message = { role: string; content: string | null; tool_calls?: ToolCall[] }
type ChatResponse = { choices: { message: Message }[] }

const chat = async (messages: unknown[]): Promise<Message> => {
  const response = await fetch(`${BASE_URL}/chat/completions`, {
    method: "POST",
    headers: { "content-type": "application/json" },
    body: JSON.stringify({ model: MODEL, messages, reasoning_effort: "none", tools: tools.map(toOpenAITool) }),
  })
  if (!response.ok) throw new Error(await response.text())
  const data = (await response.json()) as ChatResponse
  const message = data.choices[0]?.message
  if (!message) throw new Error("No choices returned from model")
  return message
}

const messages: unknown[] = []

while (true) {
  const input = await rl.question("You: ")
  messages.push({ role: "user", content: input })

  while (true) {
    const message = await chat(messages)
    messages.push(message)
    if (message.content) console.log(`Agent: ${message.content}`)
    if (!message.tool_calls?.length) break

    for (const call of message.tool_calls) {
      console.log(`[tool] ${call.function.name}(${call.function.arguments})`)
      const { content, isError } = await runTool(call.function.name, call.function.arguments)
      if (isError) console.log(`[error] ${content}`)
      messages.push({ role: "tool", tool_call_id: call.id, content: isError ? `Error: ${content}` : content })
    }
  }
}

type Tool = {
  name: string
  description: string
  parameters: Record<string, unknown> // JSON Schema, shared by both protocols
  execute: (input: unknown) => Promise<string>
  confirm?: (input: unknown) => string // describes the action; when set, the user must approve it first
}

// Reads one string field from model input, or throws a message that says how to fix it.
const field = (input: unknown, key: string, example: string): string => {
  const value = typeof input === "object" && input !== null ? (input as Record<string, unknown>)[key] : undefined
  if (typeof value !== "string") throw new Error(`${key} must be a string, e.g. ${example}`)
  return value
}

const listFiles = async (path: string) => {
  const entries = await readdir(path, { withFileTypes: true })
  return entries.map((entry) => (entry.isDirectory() ? `${entry.name}/` : entry.name)).join("\n")
}

const editFile = async (path: string, oldStr: string, newStr: string) => {
  if (oldStr === newStr) throw new Error("old_str and new_str must be different")

  if (oldStr === "") {
    if (existsSync(path)) throw new Error(`${path} already exists; pass the text to replace as old_str`)
    await mkdir(dirname(path), { recursive: true })
    await writeFile(path, newStr)
    return `Created ${path}`
  }

  const content = await readFile(path, "utf8")
  const matches = content.split(oldStr).length - 1
  if (matches === 0) throw new Error(`old_str was not found in ${path}`)
  if (matches > 1) throw new Error(`old_str matches ${matches} places in ${path}; include more surrounding text`)
  await writeFile(path, content.replace(oldStr, () => newStr))
  return "OK"
}

const saveFile = async (path: string, content: string) => {
  await mkdir(dirname(path), { recursive: true })
  await writeFile(path, content)
  return `Wrote ${content.length} characters to ${path}`
}

const TIMEOUT_MS = 30_000
const MAX_OUTPUT = 10_000

const runBash = (command: string) =>
  new Promise<string>((resolve, reject) => {
    execFile("bash", ["-c", command], { timeout: TIMEOUT_MS, maxBuffer: 10_000_000 }, (error, stdout, stderr) => {
      if (error?.killed) return reject(new Error(`The command ran longer than ${TIMEOUT_MS} ms and was stopped. Try a faster command.`))
      if (error && typeof error.code !== "number") return reject(error)
      const output = `${stdout}${stderr}`
      const shown =
        output.length > MAX_OUTPUT
          ? `${output.slice(0, MAX_OUTPUT)}\n[Output truncated after ${MAX_OUTPUT} characters. Filter it with head, tail or grep.]`
          : output
      resolve(`Exit code: ${error ? error.code : 0}\n${shown}`)
    })
  })

type ToolResult = { content: string; isError: boolean }

// Never throws: every failure becomes a result the model can read.
const runTool = async (name: string, rawArguments: string): Promise<ToolResult> => {
  try {
    const tool = tools.find((tool) => tool.name === name)
    if (!tool) throw new Error(`Unknown tool: ${name}. Available tools: ${tools.map((tool) => tool.name).join(", ")}`)

    let input: unknown
    try {
      input = JSON.parse(rawArguments)
    } catch {
      throw new Error(`The arguments are not valid JSON: ${rawArguments}`)
    }

    if (tool.confirm) {
      const answer = await rl.question(`Allow: ${tool.confirm(input)}? [y/N] `)
      if (answer.trim().toLowerCase() !== "y") throw new Error("User declined this action. Ask what they would like instead.")
    }
    return { content: await tool.execute(input), isError: false }
  } catch (error) {
    return { content: error instanceof Error ? error.message : String(error), isError: true }
  }
}

// The Anthropic protocol's wrapping of a tool. Same name and description, but the schema is called input_schema.
const toAnthropicTool = (tool: Tool) => ({
  name: tool.name,
  description: tool.description,
  input_schema: tool.parameters,
})

type TextBlock = { type: "text"; text: string }
type ToolUseBlock = { type: "tool_use"; id: string; name: string; input: unknown }
type Block = TextBlock | ToolUseBlock | { type: string } // e.g. thinking blocks: we pass them back untouched
type ChatResponse = { content: Block[]; stop_reason: string }

const isText = (block: Block): block is TextBlock => block.type === "text"
const isToolUse = (block: Block): block is ToolUseBlock => block.type === "tool_use"

const chat = async (messages: unknown[]): Promise<ChatResponse> => {
  const response = await fetch(`${BASE_URL}/v1/messages`, {
    method: "POST",
    headers: {
      "content-type": "application/json",
      "x-api-key": API_KEY,
      "anthropic-version": "2026-10-21",
    },
    body: JSON.stringify({ model: MODEL, max_tokens: 16000, messages, tools: tools.map(toAnthropicTool) }),
  })
  if (!response.ok) throw new Error(await response.text())
  return (await response.json()) as ChatResponse
}

const messages: unknown[] = []

while (true) {
  const input = await rl.question("You: ")
  messages.push({ role: "user", content: input })

  while (true) {
    const reply = await chat(messages)
    messages.push({ role: "assistant", content: reply.content })
    for (const block of reply.content) {
      if (isText(block) && block.text) console.log(`Agent: ${block.text}`)
    }
    if (reply.stop_reason === "refusal") break

    const calls = reply.content.filter(isToolUse)
    if (calls.length === 0) break

    const results = []
    for (const call of calls) {
      console.log(`[tool] ${call.name}(${JSON.stringify(call.input)})`)
      const { content, isError } = await runTool(call.name, JSON.stringify(call.input))
      if (isError) console.log(`[error] ${content}`)
      results.push({ type: "tool_result", tool_use_id: call.id, content, is_error: isError })
    }
    messages.push({ role: "user", content: results })
  }
}
Watch for this With five tools, a model may request several tools in one reply. Every call needs its own result. On the OpenAI protocol that's one role: "tool" message per call, right after the assistant message. On Anthropic it's one user message whose content starts with all the tool_result blocks. A 400 error mentioning "tool_use ids were found without tool_result blocks" indicates the results were not formatted as above.
If you have 32 GB or more of memory A larger local model tends to make fewer malformed calls, and can serve as a free second reference before using Claude. Keep building against qwen3.5:9b: code that handles a small model's mistakes also handles larger models'.
Result Adding a tool now means adding one object, and it works on every provider at once. Your tools no longer depend on your loops, and that independence is what lets OpenCode accept tools from plugins and MCP servers it has never seen.
